The application repository's `PARITY.md` is the maintenance source for capability status, acceptance checks, and Linux replacement decisions. This page is the single rendered status authority for the documentation site.

## What the badges mean

Every workflow in `PARITY.md` is marked `done`, or carries a decision status for workflows without a Linux equivalent:

- <StatusBadge status="done" /> means the workflow is usable end to end. The 1.19.x line runs on Linux (AppImage, Flatpak, source, and system installs), on Windows x86_64, and on macOS 11 or newer, so `done` rows apply on every platform unless the row's note, the platform notes below, or the macOS channel says otherwise.
- <StatusBadge status="partial" /> means a deliberate Linux equivalent exists but the Windows/premium surface is broader or unavailable.
- <StatusBadge status="missing" /> means no usable equivalent yet.
- Decision rows ("Not applicable", "Replaced by ...", "Use ... instead") mark Windows-only workflows with no Linux equivalent; they are documented as boundaries rather than implied support.

Verified against **v1.19.1** (application `docs/PARITY.md`).

## Platform coverage

The 1.19.x line runs on Linux, on Windows x86_64, and on macOS 11 or newer (Apple Silicon and Intel). The platform seam lives in `pkg/platform_compat.py` (standard library only, plus `ctypes` on Windows). Since 1.19.1 one capability contract decides which platform-specific controls each host shows: `GET /api/native/capabilities` returns a `features` object, and a missing object means every feature is unavailable. See [API 1.19 changes](/reference/api/one-nineteen/).

These surfaces remain Linux-only and are not part of the Windows or macOS builds: gamescope and Game Mode, AppImage and Flatpak packaging, XDG desktop entries, `sudo make install`, Steam Deck and handheld tuning, and Flathub-aware emulator management. See [Windows](/windows/) and [macOS](/macos/) for the platform guides.

## macOS channel (macOS 11 or newer)

Since 1.19.0 the same source tree, tests, and gates run on macOS. These rows record what is true on that channel specifically; the capability matrix below is Linux behavior.

| Capability | Status | Acceptance check |
| --- | --- | --- |
| Native window | <StatusBadge status="done" /> | `native_host_mac.m` (WKWebView) renders the same UI in a real window, with remembered geometry, `NSStatusItem` tray and minimize-to-tray, `openbox://` deeplinks, and one instance per data directory through an `AF_UNIX` socket, with the 104-byte `sun_path` limit checked before binding (1.19.0) |
| Universal install and verified update | <StatusBadge status="done" /> | `OpenBox-macos.zip` carries arm64 and x86_64 hosts and one merged interpreter; `scripts/install-macos.sh` verifies the release key anchor, the SHA-256 sidecar, and the Ed25519 signature before it installs `OpenBox.app`; the in-app updater swaps the bundle after the server exits and keeps `OpenBox.app.previous` (1.19.0) |
| No-install app | <StatusBadge status="done" /> | The bundle ships a pinned universal CPython 3.12 and the CA bundle, so the app runs without Python or WebKit installed. The installer script still needs `python3` on `PATH` to run the release verifier, and a source checkout needs Python 3.10 or newer (1.19.0) |
| Emulator detection and launch | <StatusBadge status="done" /> | Every bundled definition carries `native_exe_macos`; an app bundle resolves through `Contents/Info.plist`, and an explicit empty value means no verified macOS build, reported as not installed (1.19.0) |
| Library data location | <StatusBadge status="done" /> | `~/Library/Application Support/openbox-game-launcher`; `OPENBOX_DATA_DIR` overrides it, and stored paths keep POSIX separators so a library moves between platforms (1.19.0) |
| macOS saves | <StatusBadge status="done" /> | Save discovery covers Steam Cloud plus the documented macOS folders for PPSSPP, RPCS3, Dolphin, and RetroArch (1.19.0) |
| Notarization | <StatusBadge status="missing" /> | The bundle is ad-hoc signed. The first launch needs System Settings > Privacy & Security > Open Anyway. The release signature is verified by the installer and the updater (1.19.0, ADR 0085) |
| AppImage and Flatpak packaging | Not applicable | Linux-only channels. The macOS artifact is the signed universal zip |
| gamescope and Steam Game Mode presets | Not applicable | Linux-only. The preset, MangoHud, and handheld-performance controls are hidden on macOS, and `web_app.py --game-mode` exits with a clear message (1.19.0; capability-gated by ADR 0086) |
| Wine and Proton prefix manager | Not applicable | Wine management is a Linux surface. The panel is hidden on macOS, and `/api/wine/*` reports `available: false` (1.19.1; ADR 0086) |
| Flathub emulator management | Not applicable | Flathub is a Linux store. macOS emulators are installed by the user, and the install and folder-grant controls are hidden (1.19.1; ADR 0086) |
| Plugin sandbox | Not applicable | macOS has no bubblewrap, so the no-bwrap rule applies: plugins are skipped unless trusted or the unsandboxed override is set |

## Intentionally not replicated on Linux

Windows-only workflows without a Linux equivalent remain documented as boundaries rather than implied support. These decisions concern the Linux build; the Windows build adds no LaunchBox-only workflows either:

| LaunchBox feature | OpenBox decision |
| --- | --- |
| Windows shell replacement | Not applicable on Linux desktop environments |
| LEDBlinky / cabinet LED control | Use external Linux arcade I/O tools instead |
| Teknoparrot arcade launcher | Use Lutris/Wine launch profiles for supported titles |
| Native Xbox PC package scanning | Installed GOG, EA app, and Ubisoft Connect games import natively on Windows; Xbox PC packages still have no equivalent. On Linux use Heroic/Lutris or Xbox Cloud entries instead. |
| Bundled proprietary media packs | Replaced by free bundled media packs in OpenBox |
| LaunchBox Premium account cloud library | Replaced by OpenBox's local mounted-folder statistics sync and opt-in catalog sync plus local backups (no LaunchBox account involved) |
| LaunchBox online theme storefront | Replaced by local CSS theme import and open-folder workflow |
