The Rust server (`openbox-server`) binds to `127.0.0.1` on an ephemeral port, or the port in `OPENBOX_PORT`. This page documents the shared contract every route follows and the lifecycle a request goes through. Route lists live on the group pages. The public surface is `/api/v2/*`; the native windows use `/api/host/*`.

## Loopback boundary

- The server binds to `127.0.0.1` only, so nothing is reachable from the network. `OPENBOX_PORT` can pin the port; the default is `0`.
- OpenBoxGL does not terminate HTTPS. Use a trusted network and an external reverse proxy if you must expose it beyond the host.
- Requests carry a 30-second timeout.
- The public GET surface is `/`, `/index.html`, `/static/*.js|*.svg`, `/static/app.css`, `/static/logo.png`, `/assets/placeholder-cover.svg`, `/locales/{en,es,de,fr,pt}.json`, `/favicon.ico`, and `/favicon.svg`. Every other route requires authentication.

## Authentication

All API routes require the session token. The server writes it to `server.token` in the data directory at startup and deletes the file on exit. Two transports are accepted:

- Header: `X-OpenBox-Token: TOKEN` (preferred)
- Query parameter: `?token=TOKEN` (can leak through history and logs)

The token is compared in constant time. Authentication runs before the host-version guard, the retired-route guard, and route resolution, so an unknown route without a token returns `403`, not `404`. A missing or wrong token returns `403 {"error":"Unauthorized"}`. Ten failures in 60 seconds per IP return `429` with `code: "RATE_LIMITED"`, `retry_after`, and a `Retry-After` header; a correct token clears the bucket.

## Request lifecycle

A request flows through a fixed set of stages. Knowing the order tells you which status code you will get and why:

```text
request
 ├─ host header not loopback? → 403 BAD_HOST
 ├─ public GET path? → serve asset, no token
 ├─ method not GET/POST? → 404 ROUTE_NOT_FOUND
 ├─ missing/wrong token? → 403 Unauthorized (429 RATE_LIMITED after 10/60s)
 ├─ /api/host/* with X-OpenBox-API-Version major ≠ 2? → 409 HOST_API_UNSUPPORTED
 ├─ /api/v1/* → 410 V1_API_REMOVED
 ├─ legacy host path → 410 HOST_CHANNEL_RETIRED
 ├─ unversioned /api/* with a v2 twin → 410 API_VERSION_REQUIRED
 ├─ POST body over 65,536 bytes or not a JSON object → 400
 ├─ state schema <7 / >7 / frozen → 409 STATE_SCHEMA_TOO_OLD / STATE_FUTURE_VERSION / LIBRARY_FROZEN
 ├─ state corrupt → 503 STATE_UNAVAILABLE "OpenBox library data needs recovery…"
 ├─ handler returns ApiError → its status + stable code (GAME_NOT_FOUND, MEDIA_NOT_FOUND, …)
 └─ unhandled exception → 500 INTERNAL_ERROR "Unexpected server error. Copy the diagnostic log…"
```

Most structured error responses carry a stable `code` and a `request_id`. The request id is a short per-request token that also appears in the diagnostic log, so a screenshot of an error banner can be correlated with the log line.

Since 2.0, every error response is an `application/problem+json` (RFC 9457) document carrying `type`, `title`, `status`, `detail`, `code`, `retryable`, `request_id`, and `instance`; the `error` field is kept as a duplicate of `detail` for one compatibility cycle. The payload examples in the table below show the fields older integrations read; the full document adds the problem-details members on top.

Handlers return a typed `ApiError`; validation failures are `400` with a readable `detail`, and state errors are mapped before the handler runs (`409` for schema-too-old, future, or frozen; `503` for corrupt state). An unhandled failure is logged and returned as `500` with a `request_id`.

This is why almost every operation failure you hit through the API is a `400` with a readable, specific message, and why a `500` is genuinely "something the developers need to see," not a normal error path.

## Bodies

- POST bodies must be JSON. Bodies over 65,536 bytes are rejected with `"Request is too large."`; truncated bodies with `"Request body was truncated."`.
- The body must decode to a JSON object; `[]`, `null`, `"text"`, and malformed JSON return `400`.
- GET requests take parameters from the query string; repeated keys are parsed as lists.

## Response headers

JSON responses are served with `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and a restrictive Content-Security-Policy. Rate-limited auth returns `429` with `Retry-After`. The request timeout is 30 seconds, SSE events are capped at 64 KiB and 16 subscribers, and the webhook envelope at 64 KiB. Media files are served with immutable cache headers, ETag, Last-Modified, `Accept-Ranges`, and byte-range (206/416) support; `theme.css` revalidates with `public, max-age=0, must-revalidate` and ETag.

## Common errors

| Status | Envelope | When |
| --- | --- | --- |
| 403 | `{"error":"Unauthorized"}` | Missing or wrong token on any protected route, including `/api/v2/native/*` |
| 403 | `{"error":"Request host is not allowed.","code":"BAD_HOST","request_id":"…"}` | Host header mismatch or foreign network host rejected |
| 429 | `{"error":"Too many authentication failures. Try again later.","code":"RATE_LIMITED","retry_after":n}` | Rate limited after repeated auth failures (`Retry-After` header sent) |
| 400 | `{"error": "<message>", "code": "BAD_REQUEST", "request_id": "…"}` | Validation failures, missing prerequisites surfaced by handlers, provider errors, unknown queue/notification actions, malformed payloads |
| 404 | `{"error":"Not found","code":"ROUTE_NOT_FOUND","request_id":"…"}` | Unknown route after authentication. An unauthenticated unknown route returns `403`. |
| 404 | `GAME_NOT_FOUND` / `MEDIA_NOT_FOUND` / `DOCUMENT_NOT_FOUND` / `PLATFORM_DOCUMENT_NOT_FOUND` / `BADGE_NOT_FOUND` | Lookups that miss |
| 409 | `{"error":"Download the LaunchBox metadata database first.","code":"CONFLICT","request_id":"…"}` | Metadata routes that need the LaunchBox database (for example `GET /api/v2/metadata/search`) before it is downloaded |
| 503 | `{"error":"OpenBox library data needs recovery before this operation can continue.","code":"STATE_UNAVAILABLE"}` | Corrupt state file |
| 503 | `{"error":"Server is busy. Close an unused tab and try again.","code":"SSE_BUSY","retry_after":5}`, with `Retry-After: 5` | `GET /api/v2/events` already has its 16 subscribers |
| 500 | `{"error":"Unexpected server error. Copy the diagnostic log from Settings and include it in your report.","code":"INTERNAL_ERROR"}` | Unhandled exception |

## Versioned surface

- **Public v2 contract (`/api/v2/*`)**: The stable public API. Every `/api/v2/*` route is part of the ratcheted contract; 3.0 adds Save Vault, Achievement Trail, Deal Radar, Time Capsules, Milestones, and Backlog Itinerary on [API 3.0 changes](/reference/api/three-zero/). The 2.0 and 2.1 transitions are recorded on [API 2.0 changes](/reference/api/two-zero/) and [API 2.1 changes](/reference/api/two-one/).
- **Native host channel (`/api/host/*`)**: The authenticated channel the bundled native windows use (`launch`, `resume`, `shutdown`, `capabilities`). Host requests carry `X-OpenBox-API-Version: 2`; a mismatched major version is refused `409 HOST_API_UNSUPPORTED` before any route runs.
- **Removed surfaces**: `/api/v1/*` returns `410 V1_API_REMOVED`; the legacy host names `/api/launch`, `/api/shutdown`, and `/api/native/capabilities` return `410 HOST_CHANNEL_RETIRED`; any other unversioned `/api/*` path with a v2 twin returns `410 API_VERSION_REQUIRED`. `OPENBOX_ENABLE_V1_API` is ignored.

### Machine-Readable Error Codes

| Code | Meaning |
| --- | --- |
| `PREVIEW_NOT_FOUND` / `PREVIEW_STALE` / `PREVIEW_EXPIRED` / `PREVIEW_LIBRARY_CHANGED` | Setup preview session expired, stale, or invalidated by a library change |
| `PREVIEW_LIMIT_EXCEEDED` / `PREVIEW_ENTRY_LIMIT_EXCEEDED` | Preview exceeds the entry or payload limit |
| `UNRESOLVED_CANDIDATES` | Commit attempted while ambiguous candidates remain unresolved |
| `EMULATOR_REQUIRED` / `AMBIGUOUS_PLATFORM` / `BIOS_MISSING` | Launch Doctor preflight check codes (returned in `checks`, not as HTTP error codes) |
| `JOB_STATE_CONFLICT` | Durable operation scheduling or state conflict |
| `JOB_NOT_CANCELLABLE` / `JOB_NOT_RESUMABLE` | Operation transition disallowed in current state |
| `LIBRARY_SYNC_UNAVAILABLE` | Legacy full-library publish/pull is disabled; use the v3 preview/apply/publish catalog transport |
| `SYNC_NOT_ENABLED` | Library synchronization must be explicitly enabled before catalog operations |
| `SYNC_INVALID` / `SYNC_PREVIEW_STALE` / `SYNC_PUBLISH_STALE` | Catalog event validation failed or the local state changed since preview/publication began |

## The shared read endpoint

<ApiEndpoint method="GET" path="/api/v2/library" auth="X-OpenBox-Token: TOKEN" summary="The full public library projection, cached until the library file, media epoch, or plugin epoch changes.">

Returns `games`, `playlists`, `filter_presets`, `ra_configured`, `settings`, `discovery`, and `media_epoch`. Each game includes every editable field (with `""` defaults) plus computed flags: `id` (numeric index), `game_id` (stable), `favorite`, `hidden`, `last_played`, `play_count`, `playtime_seconds`, `path_exists`, `has_cover`/`has_background`/…, `has_saves`, `has_documents`, `has_achievements`, `tags`, `custom_fields`, `store_catalog`, `store_installed`, `owned`, and more.

In safe mode the `library` hook is skipped; otherwise plugin `library` hooks can transform the games list before it is returned (cached for 30 seconds, invalidated on state changes).
</ApiEndpoint>

## Security notes

- Treat `server.token` like a password: it grants full read/write access to the library, media, settings, and destructive operations.
- The API can read any local file path referenced by library entries (media, documents, saves). Keep local paths and exported library data private.
- Never log tokens or paste library exports into issues. The diagnostic log redacts credentials.
